# TX — unicast 送信と tx_latency（最小 4 ms）

Phase 4。v1 完了（Phase 3）のあと。アプリが PCM を書き込み、Dante ネットワークへ出す。

親: #001。Inferno ブランチ **`transmit`**（`flows_tx.rs`, `media_clock.rs`）と `dev` の `device_server/flows_tx.rs` / `tx_multicasts.rs`。`tx_multicast` ブランチは multicast TX の後続。

## v1 準備（今やる、実装は後）

設定型に `tx_latency` を持たせ、`rx_latency` と同じ下限 **4 ms** で検証する。TX チャンネル数のデフォルトは 0。

## この Issue の範囲

- TX チャンネルを DC から見えるようにする
- unicast flow 送信（9 バイトヘッダ + interleaved PCM）
- アプリ → クレートの書き込み API（`AudioBlock` の逆）
- 時計は #003 の overlay（PTP または安定したメディア時刻）
- `tx_latency` 設定可能、最小 4 ms。1 ms は狙わない

Multicast TX、PTP leader、AES67 は Later。

## 受け入れ

- DC から本クレートの TX を実機 RX にパッチし、音が届く
- Windows を第一級で確認
- `tx_latency` 4 ms で連続送信が落ちない（負荷は別測）
